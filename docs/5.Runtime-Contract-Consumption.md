# KansoBooks Runtime Contract Consumption

**Status:** Canonical / Binding

## Purpose

Runtime is a backstop and executor. It is not a second semantic authority.

Runtime consumes contract truth to:

- import files
- apply evidence policy
- call providers
- write SQLite state
- enforce local-first and consent boundaries
- execute exports
- protect against stale or malicious inputs

## Core Decision

Runtime may re-enforce static rules. Runtime must not invent them.

If runtime blocks a contract-known static issue, preflight/validator must be
able to explain the same `rule_id`.

## Runtime Responsibilities

### Filesystem

Runtime enforces:

- user-selected file access
- source file reads
- export destination writes
- destructive action confirmation
- path normalization and real filesystem checks

Contracts define which actions are allowed. Runtime enforces actual OS state.

### SQLite (operational cache)

SQLite is the regenerable cache under `.kanso/cache.sqlite`. It is NOT the
canonical source of truth per `Docs/KansoFormat.md` and `Docs/TechStack.md`.

Runtime writes contract-shaped state into SQLite for operational performance:

- validated or quarantined import records
- normalized transactions
- evidence docs and manifest frontmatter projections
- match candidates
- evidence policy and policy evaluations
- review decisions
- audit events
- journal entries
- reconciliation results
- close-gate condition states
- export runs

No runtime storage path may bypass audit requirements. Every write that
mutates derived state must first update the canonical Kanso Format folder
file (`decisions/`, `ledger/`, `audit/`) before updating SQLite; the cache
is always downstream.

### Kanso Format Folder

Runtime is the authoritative writer to the Kanso Format folder per
`Docs/KansoFormat.md`:

- `transactions/<year>/<month>.jsonl` — written after import
- `evidence/<id>.md` — written after extraction completes
- `decisions/<year>.jsonl` — written after every user decision, agent
  action, or external edit conversion; append-only
- `ledger/<year>/journal.jsonl` — written after posting; append-only
- `audit/<year>.jsonl` — written for every auditable event; append-only
- `reports/**` — written atomically at close

Runtime must enforce the file classification rules from
`Docs/KansoFormat.md` "External Edits Are Input": derived projections are
rebuilt from effective state; append-only logs are never line-edited; source
binaries are never overwritten.

### DuckDB

DuckDB is a workbench, not canonical truth.

Runtime may use DuckDB for:

- CSV profiling
- scratch transforms
- analytics queries

Runtime must write accepted output back into SQLite through contract-shaped
records before UI/export use.

### Providers

Provider runtime enforces:

- explicit consent when data leaves device
- provider capability contract
- generated request schema
- generated response schema
- timeout/retry policy
- secret redaction

Provider output is quarantined until validator accepts it.

### Export

Runtime export consumes:

- export spec
- validation result
- reviewed state
- active evidence policy
- audit metadata

Runtime must not export untraceable financial claims.

## Runtime Policy Projection

Runtime may use narrowed contract-derived projections:

```rust
pub struct RuntimeProviderPolicy {
    pub provider_id: ProviderId,
    pub data_leaves_device: bool,
    pub consent_required: bool,
    pub request_schema_id: SchemaId,
    pub response_schema_id: SchemaId,
}
```

Projection is derived from contracts, not hand-maintained.

## Path Resolution

Runtime path checks:

1. expand variables/user selections
2. normalize relative forms
3. canonicalize where applicable
4. enforce approved read/write scope
5. log source or export action

Preflight uses lexical checks. Runtime may use real filesystem resolution
because it is executing.

## External-State Failures

Runtime-owned failures include:

- file missing
- permission denied
- database locked
- provider timeout
- API key missing
- user denied consent
- disk full
- export destination unavailable

These failures should emit safe, actionable events but must not create new
static semantic rules.

Runtime-owned failure codes must have contract-owned help/recovery bindings
before they are exposed through CLI, MCP, doctor, or generated prompt
fragments.

## Audit Requirements

Runtime writes audit events for:

- import batch created
- file accepted/quarantined
- provider request started/completed/failed
- match candidates generated
- evidence policy selected or changed
- policy evaluations generated
- validation run completed
- user decision created
- transaction posted
- adjustment proposed / accepted / rejected
- auto-reversal posted
- account reconciled / difference accepted
- period closed
- opening balance set
- external edit detected and converted
- log tamper detected
- export generated (with sha256 artifact list)

Secrets and raw provider credentials must never enter audit payloads.

## Definition of Done

Runtime consumption is correct when every executing path consumes contract
truth, every contract-known block has validator parity, runtime-only failures
remain clearly runtime-only, and every exposed failure has generated
help/recovery metadata.
