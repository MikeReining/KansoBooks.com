# GUI Invariants

**Status:** Canonical / Binding

## Core Definition

A KansoBooks GUI surface is valid iff:

- backend truth enters through generated raw contracts
- transport is isolated in a gateway
- presenter owns surface salience
- state is an explicit discriminated union
- view renders curated state only
- design uses institutional white semantic tokens

## Ownership Model

| Owner | Owns |
|---|---|
| Rust/contracts | Domain truth, financial statuses, validation findings, provider policies, audit events. |
| Gateway | Tauri invoke/listen and raw transport typing. |
| Presenter | Surface-specific grouping, visibility, badges, summaries, drill-down packaging. |
| State | Renderable union and curated view models. |
| Controller | Async orchestration from gateway to presenter. |
| View | Layout and paint. |

## Locked Invariants

- UI never creates financial truth.
- UI never changes a canonical failure into success.
- UI never hides uncertainty in a way that implies correctness.
- UI never treats missing evidence as bad without showing the active policy.
- UI never bypasses redaction or consent boundaries.
- UI never hand-defines a backend payload type.
- JSX is never the first place product taste appears.
- Every non-trivial surface has a colocated `brief.md`.
- Every renderable state is named and typed.
- `empty` and `filtered_empty` remain distinct when presenter filtering exists.
- Views do not import Tauri APIs.
- Views do not import generated raw contracts.
- Presenters do not import React or Tauri APIs.
- Controllers do not duplicate presenter logic.
- Surface fixtures prove taste rules.
- White institutional design is the v1 default.

## Trust-Specific UI Rules

- Primary screen must show correctness state, not vanity metrics.
- Match reasons must be visible or one click away.
- Source evidence must be visible or one click away.
- Evidence availability and evidence requirement must be shown separately.
- Active evidence policy must be visible when it changes severity/readiness.
- Certainty gradient must be explainable and must not imply a guarantee.
- User decisions must feel reversible.
- Fatal validation findings must block export visibly.
- Cloud/provider activity must disclose data-boundary implications.
- "Ready" language is allowed only when contract rules prove readiness.

## Allowed Summarization

Presenters may:

- group low-level findings
- hide low-salience details by default
- derive friendly titles
- derive badges from contract statuses
- expose raw detail in drawers

Presenters may not:

- invent statuses
- decide policy severity outside contract-owned policy evaluation
- invent certainty gradient outside contract-owned raw state
- suppress review-required items
- remove audit context
- re-score confidence outside contract rules
- treat AI proposals as accepted truth

## Definition of Done

GUI invariants hold when every surface preserves raw contract truth, captures
product taste in briefs/presenters, and renders a calm white financial review
experience.
