# GUI Design System

**Status:** Canonical / Binding

## Core Constraint

KansoBooks v1 is institutional white.

White means:

- transparent
- calm
- financial
- verifiable
- daylight, not stealth

Do not design a dark, terminal, hacker, or developer-tool UI for v1.

## Token Rule

Use semantic CSS variables only.

Forbidden:

- raw hex values
- RGB values
- arbitrary Tailwind colors
- one-off gradient backgrounds
- dark-mode-first surfaces
- dark surfaces on light backgrounds
- dotted empty drop-zone boxes
- empty-canvas layouts

## Color Principle

KansoBooks is calm, certain, minimal, and trustworthy.

- The app must feel like a financial document, not a design experiment.
- Neutral UI first.
- Signal second.
- Blue means action or guidance.
- Green means confidence or resolved.
- Yellow means needs attention.
- Red means risk, error, or blocked.
- Color is never decoration.

## UI Role Mapping

| Element | Token rule |
|---|---|
| Primary button | `primary` background, `primary-foreground` text |
| Primary hover | `primary-hover` background |
| Secondary button | `card` background, `border` outline, `foreground` text |
| Destructive button | `destructive` background, `primary-foreground` text |
| Default card | `card` background |
| Muted card | `muted` background |
| Selected card | `primary-soft` or `accent` background |
| Matched / ready / completed | `success` |
| Needs attention | `warning` |
| Problem / blocked | `destructive` |
| Informational guidance | `info` |
| Secondary metadata | `muted-foreground` |

## Typography

Use Inter as global sans-serif.

| Role | Class |
|---|---|
| H1 | `text-2xl font-semibold tracking-normal text-foreground` |
| H2 | `text-xl font-semibold tracking-normal text-foreground` |
| H3 | `text-lg font-medium text-foreground` |
| Body | `text-sm font-normal text-foreground` |
| Meta | `text-xs font-normal text-muted-foreground` |
| Data | `font-mono text-xs font-normal text-foreground` |

No negative letter spacing. Do not scale font size with viewport width.

## Layout Rules

- Use dense, calm workspace layouts.
- The first screen must make the next action obvious.
- Intake must read as a document workflow: Add expenses, Add statement, Review.
- Prefer full-width work surfaces over decorative cards.
- Cards are for repeated items, modals, and framed tools only.
- Do not nest cards inside cards.
- Do not use dotted drop-zone boxes.
- Do not create an abstract empty-canvas first screen.
- Keep border radius at `rounded-lg` or less unless shadcn requires token use.
- Use stable dimensions for tables, lists, toolbars, counters, and status chips.
- Text must not overflow buttons, cards, or table cells.

## Component Rules

- Use `lucide-react` icons inside tool buttons.
- Use tooltips for icon-only controls.
- Use segmented controls for modes.
- Use checkboxes/toggles for binary settings.
- Use tabs only when the surface genuinely has peer views.
- Avoid explanatory in-app text about how the product works; make the workflow
  self-evident.

## Status Language

| Status | Token |
|---|---|
| Matched / ready | `success` |
| Needs attention / needs review | `warning` |
| Error / blocked | `destructive` |
| Informational | `info` |
| Secondary metadata | `muted-foreground` |

## Definition of Done

A GUI change is invalid if it makes KansoBooks feel like a dark developer tool,
uses raw colors, hides financial uncertainty, or makes verification harder.
