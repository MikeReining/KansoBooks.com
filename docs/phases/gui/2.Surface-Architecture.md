# GUI Surface Architecture

**Status:** Canonical / Binding

## Purpose

Define the surface model for KansoBooks desktop UI.

## Surface Definition

A surface is a bounded user-facing workflow area, such as:

- Intake
- Policy Setup
- Processing
- Review Workbench
- Evidence Drawer
- Export
- Settings

## Required Folder Shape

```text
apps/desktop/src/surfaces/<surface-name>/
  brief.md
  gateway.ts
  presenter.ts
  state.ts
  controller.ts
  view.tsx
  fixtures.ts
  index.ts
  presenter.test.ts
  view.test.tsx
```

Trivial shell-only layout may omit this structure. Any surface with
`presenter.ts` must have `brief.md`.

## Layer Contracts

### Raw Contracts

Source:

```text
apps/desktop/src/types/generated/
```

Owns:

- IPC request/response shapes
- event payloads
- validation finding payloads
- financial statuses
- provider/export raw data

Rules:

- generated only
- no manual edits
- may be verbose

### Gateway

Owns:

- `invoke`
- `listen`
- transport typing
- mock mode returning raw-contract-shaped fixtures

Rules:

- only layer allowed to import Tauri transport APIs
- may import generated raw contracts
- no React
- no JSX
- no product grouping or taste
- no `any`

### Presenter

Owns:

- visibility
- grouping
- human-readable titles
- badge derivation
- issue ordering
- drill-down packaging
- empty vs filtered-empty distinction

Rules:

- pure TypeScript
- deterministic
- fixture-testable
- may import generated raw contracts and `state.ts`
- no React
- no Tauri
- no network/filesystem

### State

Owns:

- discriminated union of renderable states
- curated view models

Rules:

- local handwritten types
- no raw backend payload leakage into views
- clear discriminator such as `status`

### Controller

Owns:

- TanStack Query orchestration
- gateway call
- presenter call
- loading/error mapping into surface state

Rules:

- thin
- no salience logic
- no raw transport in view

### View

Owns:

- layout
- component composition
- semantic token usage
- accessible controls

Rules:

- render state only
- branch with `switch` or clear early returns
- no raw contracts
- no gateway/presenter imports
- no financial decisions

## Import Boundary Matrix

| File | May import | Must not import |
|---|---|---|
| `gateway.ts` | Tauri APIs, generated contracts | React, JSX, views, presenter taste |
| `presenter.ts` | generated contracts, `state.ts` | React, Tauri, gateway |
| `state.ts` | local type helpers | Tauri, JSX, gateway |
| `controller.ts` | React hooks, TanStack Query, gateway, presenter, state | design/taste rules, JSX layout |
| `view.tsx` | state, controller, components/icons | Tauri, generated contracts, gateway, presenter |
| `fixtures.ts` | state, generated raw contracts for mock data | real transport |

## MVP Surfaces

Build in this order:

1. Intake
2. Policy Setup
3. Processing
4. Review Workbench
5. Evidence Drawer
6. Export
7. Settings

## Definition of Done

A surface is complete when its brief, state, presenter, fixtures, tests,
gateway, controller, and view obey these boundaries.
