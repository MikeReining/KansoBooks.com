# GUI Enforcement and Test Wall

**Status:** Canonical / Binding

## Purpose

Make GUI drift fail fast.

## Enforcement Surfaces

CI/local checks should enforce:

1. generated raw-contract currency
2. import/layer boundaries
3. IPC envelope consistency
4. presenter and state coverage
5. view render coverage
6. design token usage
7. no dark-theme regression

## Generated Raw Contracts

- Build fails if Rust-generated frontend bindings are stale.
- Surfaces compile against generated raw contracts only.
- Handwritten backend mirror types are forbidden.

## Import Boundaries

| File | Forbidden |
|---|---|
| `view.tsx` | Tauri APIs, generated raw contracts, gateway, presenter |
| `presenter.ts` | React, Tauri APIs, gateway |
| `gateway.ts` | React, JSX, product taste |
| `controller.ts` | product grouping/filtering/taste |
| `fixtures.ts` | real transport |

Additional bans:

- `any` in gateway or surface code
- `as any`
- raw color utilities
- raw hex/RGB
- production imports from fixtures

## IPC / Gateway Wall

- Every Tauri invoke used by surfaces routes through a gateway.
- Gateway input/output is typed to generated contracts.
- Mock mode must preserve raw-contract shape.
- Wrong top-level payload keys should fail in dev/test once envelope checks
  exist.

## Presenter Test Wall

Every `presenter.ts` must have tests covering:

- ready state
- empty state
- error state when presenter owns error mapping
- filtered_empty when filtering exists
- noisy raw data
- all brief-owned taste rules
- trust/evidence visibility rules
- evidence-policy display rules

Presenter tests run without:

- Tauri
- network
- filesystem
- React DOM

## View Render Wall

Every declared state has a render path.

Render tests must prove at least:

- loading
- error
- empty
- ready
- primary action availability

Visually complex surfaces should add screenshot checks once Playwright or an
approved visual tool is introduced.

## Design Wall

Fail or fix when:

- raw colors appear
- dark backgrounds dominate
- gradients/orbs/developer styling appear
- text overflows controls
- status color is not token-driven
- issue/review states are visually hidden

## MVP Manual GUI Smoke

Run before founder demos:

1. launch app
2. create/open local business file
3. drop bank CSV
4. drop receipts
5. process batch
6. inspect one match reason
7. switch Lean/Strict policy on fixture data
8. confirm missing evidence changes severity without changing facts
9. correct one ambiguous match
10. mark statement as sufficient under policy
11. export CSV/report
12. confirm white institutional UI throughout

## Definition of Done

GUI enforcement is working when stale contracts, boundary violations, missing
presenter coverage, missing render states, and non-white design regressions fail
before founder review.
